Digital Systems II, RIT

A RISC processor in VHDL

A reduced instruction set processor I designed from the datapath up, wrote in VHDL, and verified by running real programs on it.

  • When: October to December 2025
  • Tools: VHDL, Quartus Prime, ModelSim, FPGA board
  • My role: Individual project

The design

Each student received a different processor specification based on an assigned ID number. Mine called for:

MemoryHarvard architecture, with separate program and data memory
DatapathTwo internal buses
ALUBuilt structurally from smaller components
Input and outputSeparately mapped, using IN and OUT instructions
Shift and rotateShift left (SHLL) and rotate right through carry (RRC)
Conditional jumpTaken when the selected status bit is 1
Control unit styleIF-ELSE statements in VHDL

The register file holds four general registers (R0–R3), and a status register tracks carry, negative, overflow, and zero (C, N, V, Z).

How an instruction runs

The control unit steps every instruction through a sequence of machine cycles and raises the right load signals at each step:

  • MC0 and MC1: fetch the instruction from program memory and decode it.
  • MC2: load the operand register. Single-step operations like SHLL and RRC finish here and return to MC0, since the two-bus datapath can complete them in one cycle.
  • MC3: do the main operation, such as an ALU add. For loads, stores, and jumps, this cycle builds the memory address by adding a base and an offset into the memory address register.
  • MC4: read or write data memory, or take the jump if its condition is met.

A result-select mux (D_Sel) chooses whether a register gets its new value from the ALU, data memory, or the input port.

Debugging

Most of the work was tracing instructions cycle by cycle in ModelSim. Two problems took the longest:

  • The wrong register was being loaded. My control unit didn't specify every load signal in every case, so a register could change when it shouldn't. I rewrote each case to set all load signals explicitly and added a safe default that turns every load off.
  • An instruction misbehaved in the test program. Working around it with a dummy instruction threw off the program's address assignments. Tracking down and fixing the addressing took a long time, and I got it working before the deadline.

Result

To prove the whole processor worked, it ran a program that multiplies two 4-bit numbers entered on the switches. Multiplying 1111 by 1111 (15 × 15):
